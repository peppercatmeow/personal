How it works

The adapter

LoRA freezes the base weight W and learns a low-rank delta: W′ = W + B·A, where B is d×r (initialized to zero) and A is r×k (small random init). Zero-init on B means the model behaves exactly like the base model at step zero.

What rank r does

Rank is the bottleneck dimension — the capacity knob. Trainable params grow linearly in r (r·(d+k) per matrix), so doubling rank doubles adapter size. Too low and the adapter can't express the behavior change; too high and you're paying full-fine-tune prices for LoRA convenience. r=8–32 covers most real tasks.

What to adapt

The classic recipe adapts attention projections — q_proj and v_proj, often all of q/k/v/o — which is enough for style and formatting shifts. Adding the MLP blocks (gate/up/down_proj) roughly triples adapter params and helps heavier domain shifts, at the cost of more memory and overfitting risk on small datasets.

QLoRA

Same adapters, cheaper base: the frozen model is quantized to 4-bit (NF4, 0.5 bytes/param) while adapters train in bf16 with 8-bit Adam. That's how an 8B-class fine-tune fits in ~4 GB of weight memory instead of 112 GB.

When fine-tuning beats RAG

RAG wins when knowledge is missing or changes — retrieval stays fresh without retraining. Fine-tuning wins when the gap is behavioral: tone, format, domain phrasing, tool-use patterns. It's also the latency play: a baked-in behavior costs one forward pass, while RAG pays retrieval + a longer context on every query.
