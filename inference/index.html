Fleet simulator

Requests arrive as a Poisson process. Each replica serves a running batch with a fixed token budget per tick (continuous batching). An autoscaler adds or removes replicas based on p95 latency and queue depth.

Autoscaler evaluates every 2s: scale up if p95 > target or queue > 40 · scale down after 3 consecutive calm evals (p95 < ½ target and empty queue). Min 1, max 8 replicas.

How it works

Prefill vs decode. The first forward pass over the prompt (prefill) is compute-bound — big dense matmuls that saturate the GPU's FLOPS. Every token after that (decode) is memory-bandwidth-bound: the full weight matrix must be streamed from HBM for a single token's worth of math. That's why decode throughput, not prefill, determines serving capacity.

Continuous batching. Instead of waiting for a full static batch, the scheduler admits new requests into the running batch the moment a slot frees. In this sim each replica holds up to 32 active requests and spreads its per-tick token budget evenly across them — the throughput gain from batching is sublinear, which is why latency climbs steeply past saturation.

KV cache. For each layer, each token's key and value vectors (2 × kv_heads × head_dim elements) are stored for the whole sequence, so attention over past tokens is O(1) per step instead of recomputed. GQA (fewer KV heads than attention heads) shrinks this cache linearly — the main reason 8B-class models can serve long contexts on one GPU.

Autoscaling. The controller samples p95 end-to-end latency (queue + service) and queue depth every 2s. Scale-up is aggressive (one replica per eval while p95 > target or queue > 40); scale-down requires 3 consecutive calm evals, which avoids flapping when traffic is bursty.

Cost math. At $2.50/GPU-hr per replica, cost per million tokens = replicas × 2.50 / (measured tok/s × 3600) × 10⁶. It falls as throughput rises — batching harder is cheaper per token — and jumps when the autoscaler adds a replica.

Honest note: the per-replica service rate (~2500 tok/s for an 8B-class model on H100-class hardware) is a calibrated constant, not a real model. Prefill is modeled as burning budget ~32× faster than decode rather than simulated as a separate phase — directionally right (prefill is compute-bound) but the factor is a simplification. Real fleets also contend on interconnect, preemption, and chunked-prefill scheduling, none of which this sim captures.
