RAG service with an eval harness

Hybrid retrieval over a doc corpus, tunable chunking, and an eval harness for before/after config comparison.

Eval harness

6 labeled queries. Run eval scores the current config; save it as a baseline, change the config, run again to see the delta.

Metric definitions
P@k (precision@k)
Share of the top-k retrieved chunks that come from a relevant document.
R@k (recall@k)
Retrieved relevant chunks divided by the number of relevant documents.
RR (reciprocal rank)
1 ÷ the rank of the first relevant chunk; 0 when no relevant chunk is retrieved.
Averages
Mean of each metric across the 6 labeled queries.
Deltas
Current config minus the saved baseline. Green Δ means the change helped; red ∇ means it hurt.

How it works

  • BM25 (k1=1.5, b=0.75).

    Sparse lexical scoring over term frequency, inverse document frequency, and document-length normalization. Strong on exact terms — error codes, API names, model names — and still the baseline every dense system has to beat.

  • TF-IDF cosine is the in-browser stand-in for dense embeddings.

    Same geometry as dense retrieval — cosine similarity over weighted vectors — with none of the semantics. It shows how the pipeline behaves when you trade lexical matching for vector similarity. In production you would use a real embedding model and an ANN index instead of brute-forcing a few dozen vectors.

  • Hybrid fuses the two signals.

    Each score is min-max normalized to [0,1] over the corpus, then combined as α·vector + (1−α)·lexical. α tunes the semantic/lexical trade-off — the right value comes from the eval set, not intuition.

  • Chunking happens at index time.

    Each document is split into N roughly equal word windows, and retrieval scores chunks, not documents. Oversized chunks dilute term statistics; undersized chunks lose the context a generator needs. Measure it, don't guess it.

  • What production adds.

    pgvector or FAISS (HNSW) for approximate nearest-neighbor search at scale, a cross-encoder reranker over the top-k candidates, and this same before/after eval discipline on every pipeline change.

Honest label: the algorithms are real — this is actual BM25 and actual cosine similarity, not a mock. The corpus is a toy (12 documents), so treat absolute scores as illustrative and relative deltas as the signal.
